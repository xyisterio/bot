# Разговорный Telegram-бот (grammy + Groq)

## Локальный запуск (проверить перед деплоем)

```bash
npm install
cp .env.example .env
# впиши BOT_TOKEN и GROQ_API_KEY в .env
npm start
```

## Деплой на Render

1. Залей этот проект в GitHub-репозиторий (без `.env` — он в `.gitignore`)
2. На Render: **New → Web Service** → подключи репозиторий
3. Настройки:
   - **Runtime:** Node
   - **Build command:** `npm install`
   - **Start command:** `npm start`
4. **Environment → Add Environment Variable:**
   - `BOT_TOKEN` — токен от @BotFather
   - `PROVIDER_ORDER` — например `gemini,groq,huggingface,openrouter`
   - `GEMINI_API_KEYS` — один или несколько ключей с aistudio.google.com/apikey через запятую (несколько аккаунтов = суммарно больше дневной квоты, см. раздел "Несколько ключей Gemini" ниже); старое имя `GEMINI_API_KEY` тоже работает, если ключ один
   - `GEMINI_MODEL` — например `gemini-2.5-flash`
   - `GROQ_API_KEY` — ключ с console.groq.com (нужен как минимум для фолбэка)
   - `GROQ_MODEL` — например `openai/gpt-oss-120b,llama-3.3-70b-versatile`
   - `HUGGINGFACE_API_KEY` — токен с huggingface.co/settings/tokens (права "Make calls to Inference Providers")
   - `HUGGINGFACE_MODEL` — например `meta-llama/Llama-3.3-70B-Instruct,Qwen/Qwen2.5-72B-Instruct`
   - `OPENROUTER_API_KEY` — ключ с openrouter.ai/keys
   - `OPENROUTER_MODEL` — например `meta-llama/llama-3.3-70b-instruct:free,qwen/qwen3-coder:free`
   - `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` — чтобы память бота (история, алиасы, пол, активная модель) не сбрасывалась при рестартах. Без этих двух переменных бот всё равно работает, просто без сохранения памяти. Подробности — в разделе "Память между рестартами" ниже.

   Подробности и актуальный список переменных — в разделе "Модели и провайдеры" ниже.
5. Deploy. В логах должно появиться `Бот запущен (long polling)`

## Чтобы бот не засыпал (free tier спит через 15 мин простоя)

Зарегистрируйся на cron-job.org (бесплатно), создай задачу, которая раз в
10 минут дёргает GET-запрос на URL твоего Render-сервиса
(вида `https://твой-сервис.onrender.com/`).

## Память между рестартами (Upstash Redis)

Без этого история переписки, алиасы, пол собеседников и то, на какой
модели бот сейчас отвечает, живут только в оперативной памяти процесса —
и обнуляются при каждом рестарте/передеплое на Render (а free tier ещё и
засыпает сам по себе).

Чтобы это не терялось:

1. Зарегистрируйся на upstash.com (бесплатно), создай базу Redis.
2. В консоли базы — вкладка **Details → REST API** — скопируй
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
3. Добавь их в Environment Variables на Render (см. шаг 4 выше).
4. Передеплой. В логах при старте должна появиться строка вида
   `Восстановлено из Redis: истории — N, алиасы — N, ...`

Если переменные не заданы — бот работает как раньше, просто без
сохранения памяти (в логах будет предупреждение об этом при старте).

## Как поменять манеру общения бота

Открой `index.js`, найди константу `SYSTEM_PROMPT` в начале файла —
это единственное место, которое нужно менять. Перепиши текст под новый
характер, закоммить и запушь — Render передеплоит автоматически.

## Погода

Работает без всяких API-ключей (используется бесплатный Open-Meteo,
геокодинг + прогноз) — просто напиши боту (с обращением, как обычно):

- `погода в Киеве` — текущая погода: температура, ощущается как, влажность, ветер
- `погода в Киеве на 10 дней` (или `на неделю`) — прогноз по дням с иконками,
  датами и вероятностью осадков

Города понимаются на любом языке (в том числе по-русски в разных падежах —
"в Киеве", "в Одессе" и т.п.) и для любой точки планеты, не только из
захардкоженного списка.

## Шахматы и шашки

Напиши боту `шахматы` или `шашки`, чтобы начать партию — дальше просто пиши
ходы (`e2e4`/`Nf3` в шахматах, `b6-c5`/взятие `b6:d4` в шашках). Бот отвечает
ходом в той же нотации, в которой пишешь ты сам. Под доской теперь всегда
виден счёт — сколько и каких фигур/шашек съедено у каждой стороны.
Команды внутри партии: "покажи доску", "новая партия", "играй за белых",
переключение вида ("фигурками"/"буквами"), "сдаюсь".

## Крокодил

Напиши `/krokodil` (или боту `крокодил`) — появится кнопка "🐊 Хочу быть
ведущим". Кто нажал — выбирает сложность слова (🟢 лёгкое / 🟡 среднее /
🔴 сложное) и получает слово **лично себе** — Telegram показывает такой
алерт только нажавшему, даже в общем чате, остальным слово не видно.
Дальше ведущий объясняет слово (жестами, синонимами — само слово и
однокоренные говорить нельзя), а остальные участники чата просто пишут
отгадки обычными сообщениями — обращаться к боту по имени не нужно.
Угадал — раунд закрывается, начисляется очко, открывается кнопка для
следующего ведущего. У ведущего под сообщением есть свои кнопки:
показать слово ещё раз (если закрыл алерт), другое слово той же
сложности, сдаться (раскрывает слово всем и завершает раунд).

Счёт копится по игрокам чата и не сбрасывается между раундами (таблица
лидеров показывается после каждой отгадки и по команде `/krokodil`, пока
раунд не идёт).

Словарь слов не зашит в код: при каждом старте бот сам скачивает и
пересчитывает его из двух открытых источников на GitHub — частотный
список русских слов (по частоте встречаемости в живой речи) и список
русских существительных, пересечение даёт слова, отсортированные от
самых обиходных к самым редким. Получается несколько тысяч слов на
уровень сложности, без повторов, пока не пройден весь пул. Если на
старте GitHub недоступен — бот на время остаётся на маленьком встроенном
запасном словаре (десяток-другой слов на уровень), а при следующем
рестарте пробует скачать полный список снова.

## Фото в группе

Каждое фото, присланное в группу (даже без обращения к боту), тихо
уходит на отдельную vision-модель — `qwen/qwen3.6-27b` на Groq
(`GROQ_VISION_MODEL` в `.env`, если понадобится сменить). Основные
диалоговые модели (Gemini и т.п.) картинку не видят и не тратят на неё
токены — вместо этого короткое текстовое описание (1 предложение,
по-русски) кладётся:

1. в лог для пересказа (см. "Пересказ чата" ниже) — так что "Женя, о чём
   тут речь?" может упомянуть и то, что было на фото;
2. в обычную историю диалога чата — так что если позже кто-то спросит
   бота "а что было на фото", модель, которая будет отвечать (необязательно
   Groq — какая угодно из фолбэка), уже увидит описание в контексте.

Бот на само фото ничего не отвечает — это фоновая обработка, а не реакция
на сообщение. Фото от других ботов игнорируются. Ограничение: обычная
история диалога держит всего последние 12 сообщений (`HISTORY_LIMIT`), так
что в очень активном чате с частыми фото упоминание может довольно быстро
"вытолкнуться" реальными репликами — для долгой памяти о фото полагайся на
пересказ чата, а не на обычный диалог.

## Пересказ чата ("о чём тут речь?")

Работает только в группах. Обратись к боту как обычно (по имени/реплаем/тегом)
и спроси что-то вроде:

- `Женя, о чём тут речь? 100`
- `Женя, что я пропустил, 50 сообщений`
- `Женя, перескажи чат`

Число — сколько последних сообщений взять (максимум 300); если не указать —
берётся 50 по умолчанию. Бот пройдётся по последним сообщениям чата
(сообщения других ботов туда не попадают) и коротко перескажет, кто о чём
говорил. Если кто-то за этот период в основном переписывался с самим ботом,
а не с остальными — по нему будет отдельный пункт вида "Имя общался(-ась) с
ботом о том-то", без раскрытия подробностей самого диалога.

Лог сообщений для пересказа копится отдельно от обычной памяти диалога
(`history:*` в Redis) под ключом `chatlog:*` — тоже переживает рестарт,
если настроен Upstash Redis (см. раздел "Память между рестартами" выше).

## Команды бота

- `/start` — начать (сбрасывает память диалога)
- `/reset` — очистить историю переписки, если бот "путается" в контексте
- `/krokodil` — сыграть в крокодил / посмотреть статус раунда и таблицу лидеров

## Модели и провайдеры (фолбэк между сервисами)

Бот умеет пробовать несколько провайдеров и моделей по очереди — если
текущая недоступна (сняли с платформы, кончились лимиты, временная
ошибка), автоматически переключается на следующую и запоминает рабочую,
чтобы не дёргать мёртвую на каждый запрос.

**Переменные окружения:**

```
PROVIDER_ORDER=gemini,groq,huggingface,openrouter    # порядок провайдеров слева направо
GEMINI_API_KEYS=...,...             # 1+ ключей с aistudio.google.com/apikey через запятую (см. ниже)
GEMINI_MODEL=gemini-flash-latest,gemini-3.5-flash       # можно списком через запятую
GROQ_API_KEY=...                    # ключ с console.groq.com/keys
GROQ_MODEL=openai/gpt-oss-120b,llama-3.3-70b-versatile
HUGGINGFACE_API_KEY=...             # токен с huggingface.co/settings/tokens
HUGGINGFACE_MODEL=meta-llama/Llama-3.3-70B-Instruct,Qwen/Qwen2.5-72B-Instruct
OPENROUTER_API_KEY=...              # ключ с openrouter.ai/keys
OPENROUTER_MODEL=meta-llama/llama-3.3-70b-instruct:free,qwen/qwen3-coder:free
```

Провайдер без заданного ключа просто пропускается — например, если
`GEMINI_API_KEYS` (или старый `GEMINI_API_KEY`) не задан, бот сразу пойдёт в Groq.

**Про Gemini:**
- Бесплатный тир: ориентировочно 10–15 запросов/мин, ~1000–1500 запросов/день на актуальной Flash-модели (Google периодически режет лимиты и снимает старые модели с доступа — точные цифры смотри в кабинете aistudio.google.com после получения ключа)
- `gemini-flash-latest` — это алиас, который Google сам переключает на актуальную GA Flash-модель, так что он меньше ломается со временем, чем захардкоженное имя вроде `gemini-2.5-flash` (эту модель Google уже отрезал для новых ключей раньше официальной даты депрекации)
- Заметно живее и умнее ламы/квена — это полноценная фронтир-модель, а не открытая уменьшенная
- На бесплатном тире Google может использовать переписку для обучения моделей — учитывай это, если в чате будут чувствительные данные
- ⚠️ На практике реальный лимит для новых бесплатных ключей может оказаться сильно жёстче заявленного — например, у `gemini-3.5-flash` free tier видели квоту всего **20 запросов в сутки** (не в минуту — именно в сутки, `GenerateRequestsPerDayPerProjectPerModel-FreeTier`). Это дневная, не минутная квота — при 5-минутном `MODEL_COOLDOWN_MS` бот будет весь день безуспешно дёргать gemini каждые 5 минут и падать в лог теми же 429, пока квота не сбросится около полуночи по времени Google (обычно Pacific Time). На фолбэк на остальных провайдеров это не влияет, просто шум в логах — если раздражает, можно поднять `MODEL_COOLDOWN_MS` или убрать gemini из `PROVIDER_ORDER`.

**Несколько ключей Gemini (несколько аккаунтов) — `GEMINI_API_KEYS`:**

Раз у free tier лимит именно дневной и довольно скромный, самый практичный
способ его увеличить — не платить, а завести ключи на нескольких Google-
аккаунтах и перечислить их через запятую:

```
GEMINI_API_KEYS=ключ_с_аккаунта_1,ключ_с_аккаунта_2,ключ_с_аккаунта_3
```

Механика переключения — та же самая, что уже используется для фолбэка
между моделями/провайдерами (единый список целей + cooldown на каждую),
никакой отдельной логики не понадобилось. Каждая пара
"модель + ключ" — это отдельная независимая цель:
как только у одного ключа кончается дневная квота (Gemini отвечает 429),
эта конкретная цель уходит в cooldown (`MODEL_COOLDOWN_MS`), а бот на
следующий же запрос пробует ту же модель со **следующим ключом** — и
только когда закончатся вообще все ключи для этой модели, переходит к
следующей модели/провайдеру по обычному порядку фолбэка. Так суммарная
дневная квота — это примерно (лимит одного free-аккаунта) × (число ключей).

`/model` и логи при этом показывают, какой именно аккаунт сейчас
используется/в кулдауне — метка вида `gemini/gemini-flash-latest (аккаунт 2)`.

Старый одиночный `GEMINI_API_KEY` по-прежнему работает как раньше (просто
один ключ = один аккаунт) — переписывать `.env` не обязательно, если
несколько аккаунтов не нужны.

**Про Groq (используется как фолбэк):**
⚠️ Groq регулярно снимает модели с платформы. Актуальный список — console.groq.com/docs/models,
депрекации — console.groq.com/docs/deprecations. При 404 model_not_found — модель уже не существует, замени в `GROQ_MODEL`.

**Про Hugging Face Inference Providers:**
- Единый OpenAI-совместимый роутер (`router.huggingface.co`), который под капотом маршрутизирует запрос к одному из нескольких сторонних бэкендов (Together AI, Fireworks, Cerebras и др.) — какой именно бэкенд обслужит конкретный запрос, решается на их стороне динамически
- Бесплатный тир: ориентировочно ~1000 запросов/день на общей инфраструктуре, латентность может плавать (первый запрос к "холодной" модели — 30–60 секунд)
- Модели по умолчанию (`Llama-3.3-70B-Instruct`, `Qwen2.5-72B-Instruct`) — того же уровня, что и модели у Groq, не тупее
- ⚠️ **Приватность:** так как роутер выбирает бэкенд динамически, политика хранения/использования переписки для обучения зависит от того, какой именно провайдер обслужил запрос — единой гарантии от самого Hugging Face по умолчанию нет. Перед использованием зайди в **huggingface.co/settings/inference-providers** и там вручную отключи (или явно разреши только нужных) провайдеров — эта настройка привязана к аккаунту, из `.env`/кода она не управляется и делается один раз

**Про OpenRouter:**
- Агрегатор с моделями с суффиксом `:free` — доступ полностью бесплатный, но состав ротируется: провайдеры добавляют/убирают бесплатные модели без предупреждения, так что раз в пару месяцев стоит сверяться со списком на openrouter.ai/models с фильтром `free`
- Бесплатный тир: 20 запросов/мин + 50 запросов/день без пополнения баланса, либо 1000/день после разовой покупки от $10 кредитов (лимит остаётся навсегда, даже если сами кредиты потрачены на что-то другое)
- Модели по умолчанию (`llama-3.3-70b-instruct:free`, `qwen3-coder:free`) — открытые модели, качество сопоставимо с тем, что уже используется у Groq/HF
